# 教程 2：在现有 DHCP 网络上叠加 PXE

> ⏱ 预计用时：10 分钟 ｜ 难度：初级 ｜ 读者：网络里已有 DHCP 服务器，想叠加网络引导能力
> 前置条件：PxeLab 已启动（见[快速开始](../getting-started.md)）、一台支持网络引导的客户端、客户端与 PxeLab 二层网络互通

---

## 场景

公司网络里已经有一台 DHCP 服务器（例如网关 `192.168.1.1` 兼任），所有设备都在正常上网。现在想在不改动现有 DHCP、不影响任何设备的情况下，给网络叠加 PXE 引导能力——比如批量给几台机器装系统。

这正是 **proxy 模式**的用武之地：**IP 地址仍由现有 DHCP 分配，PxeLab 只负责提供 PXE 引导信息**。

```
现有 DHCP (192.168.1.1)          PxeLab (192.168.1.100)
      │                                │
      ├─ 分配 IP ──► 客户端 ◄── 引导信息（proxy，端口 4011）
```

---

## 准备

- PxeLab 服务器 IP（示例：`192.168.1.100`），与客户端**同一二层网段**（proxy 依赖广播，跨 VLAN 需要配置 DHCP 中继）
- 公司网段（示例：`192.168.1.0/24`）
- 客户端支持 PXE 网络引导

---

## 第 1 步：新增接口，选择 proxy 模式

进入 **基础配置 → 服务配置 → DHCP**，点击右上角「**新增接口**」，填写：

| 字段 | 示例值 |
|------|--------|
| 接口名称 | `eth0`（或从列表选择检测到的网卡） |
| IP 地址 | `192.168.1.100`（PxeLab 服务器 IP） |
| 子网 1 → 子网 CIDR | `192.168.1.0/24`（公司网段） |
| 子网 1 → DHCP 模式 | `proxy（Proxy DHCP）` |

**地址池、网关、DNS 留空**——proxy 模式不分配 IP，这些字段无需配置（界面会提示）。

保存。

## 第 2 步：确认 ProxyDHCP 服务运行

检查顶部**服务状态栏**：`ProxyDHCP`（端口 4011）应为「运行」；若不是，点击启动。

## 第 3 步：客户端开机，进入网络引导

客户端开机，进入启动菜单（F12 / F11 / Esc），选择**网络引导**。

引导过程会变成两个来源协作：

1. 现有 DHCP 给客户端分配 IP
2. PxeLab 提供引导文件地址与引导信息

如果一切正常，几秒内会出现 PxeLab 引导菜单——从这一步起，后续流程与教程 1 完全相同（选择 OS 安装目录、安装系统等）。

## 第 4 步：验证

- 客户端拿到了 IP（现有 DHCP 分配的），**且**出现了 PxeLab 引导菜单——两者同时满足即成功
- 原有网络上的其他设备一切照常（proxy 不响应非 PXE 客户端）

---

## 本教程常见问题

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 客户端拿到 IP 但没有引导菜单 | 二层不通 / UDP 4011 被防火墙拦截 | 确认客户端与 PxeLab 同网段；放行 UDP 67/4011 |
| 菜单不出现，且 DHCP 有 PXE 选项冲突 | 现有 DHCP 也提供了 PXE 选项 | 在现有 DHCP 上关闭 PXE/引导选项（保留 IP 分配） |
| 跨 VLAN 客户端无响应 | proxy 模式依赖广播 | 在交换机/路由器上为客户端网段配置 DHCP 中继指向 PxeLab |
